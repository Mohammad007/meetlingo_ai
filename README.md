# MeetLingo AI

Android app that turns spoken English into live English + Roman-script **Hinglish** captions — entirely on the phone.
No backend, no login, no cloud: speech recognition (sherpa-onnx), translation (Google ML Kit, on-device) and storage (SQLite) all run locally. After the models are downloaded once, meetings work in airplane mode.

**Status:** runs end-to-end on a real device (tested on a Motorola Edge 50 Pro, Android 15): live mic → English captions → Hinglish, saved to local history, working offline. Release APK builds locally (debug-signed).

## Features

| Area | Implementation |
| --- | --- |
| Speech → English | sherpa-onnx 2.0.1 streaming transducer on a native Kotlin inference thread, endpoint detection, interim + final captions, 2–4 CPU threads (cores/2) |
| English → Hindi | Google ML Kit Translation (on-device, model downloaded once) |
| Hindi → Hinglish | Rule-based romanisation with schwa deletion, English loanword/greeting restoration, colloquial normalisation, user glossary (keep-in-English, translate-as, spelling overrides); optional Android ICU transliteration |
| Audio focus | Silero VAD voice-only filter (bundled, 644 KB), Android noise suppression + auto gain, preferred microphone direction (Android 10+), filler/noise caption filter — all user-configurable, only reported as active when the device supports them |
| Audio pipeline | `AudioRecord` 16 kHz mono (explicit resampling from 48/44.1 kHz), bounded queue with drop telemetry, foreground service (`microphone` type) with notification Pause/Resume/Stop, mic released on pause |
| Storage | expo-sqlite, versioned migrations (`PRAGMA user_version`), transactions, foreign keys, FTS5 search with LIKE fallback, crash recovery (meetings marked `interrupted`), orphaned-session cleanup on startup |
| Screens | All 26 screens from the spec (Expo Router): onboarding, permissions, model setup/manager, live captions, full-screen, overlay, history, transcript, search, summary, action items, export, glossary, settings, diagnostics… |
| Exports | TXT (bilingual), SRT, PDF (two-column / stacked) via share sheet or system folder picker |
| Same-phone meetings | Honest MediaProjection/AudioPlaybackCapture test; call audio is reported as not capturable (see `docs/audio-capture-limitations.md`) |
| Branding | Custom app icon (adaptive + Android 13 themed/monochrome) and splash screen |

Not included in V1, by design: cloud/BYOK engines, speaker diarisation, generative summaries, a laptop companion app.

## Stack

Expo SDK 58 (React Native 0.88, New Architecture, React Compiler) with **development builds** (`expo-dev-client`) — not Expo Go. Native code lives in a local Expo module (`modules/meetlingo-native`, Kotlin); `android/` is generated by `expo prebuild` and is not committed. State: Zustand. Navigation: Expo Router.

> The original spec asked for a "bare workflow". This repo follows the project's `AGENTS.md` (Expo + Continuous Native Generation). The result is equivalent: a Gradle/Kotlin Android app with custom native modules, but native config is reproducible from `app.json` + the module instead of hand-edited.

## Requirements

- Node 20+ (tested 22.22), JDK 17, Android SDK (compileSdk 37; NDK/CMake installed by Gradle as needed)
- A real **ARM64 Android 8.0+ phone** (minSdk 26). Android 10+ for mic focus and the same-phone capture test.
- **Windows only** — React Native's C++ build exceeds the 260-character path limit. Before the first native build:
  1. Enable long paths (Administrator PowerShell):
     `New-ItemProperty -Path "HKLM:\SYSTEM\CurrentControlSet\Control\FileSystem" -Name LongPathsEnabled -Value 1 -PropertyType DWORD -Force`
  2. Replace `%LOCALAPPDATA%\Android\Sdk\cmake\3.22.1\bin\ninja.exe` with [ninja 1.12.1](https://github.com/ninja-build/ninja/releases/tag/v1.12.1) (1.10.x is not long-path aware). Keep a backup of the old file.
  3. Optional: exclude the project folder from antivirus scanning — it has caused transient "file not found / locked" Gradle errors.

## Build & run (development)

```bash
npm install            # also downloads + SHA-256-verifies the sherpa-onnx AAR (scripts/fetch-native-deps.js)
npm run prebuild       # generates android/ from app.json and the native module
npm run android        # builds the dev client and installs it on the connected device (adb)
npm start              # Metro for the dev client (keep the phone on USB or the same Wi-Fi)
```

Run only one Gradle build at a time in `android/` — parallel builds corrupt intermediate outputs. If a build fails with missing classes or a missing `libreactnative.so` at launch, stop Gradle (`cd android && ./gradlew --stop`), delete `android/app/build` and the `node_modules/*/android/build` folders, and rebuild.

## Release APK

```bash
npm run prebuild
cd android && ./gradlew assembleRelease -PreactNativeArchitectures=arm64-v8a
# android/app/build/outputs/apk/release/app-release.apk  (~95 MB, JS bundle embedded, no Metro needed)
```

- Built APKs are copied to `release/` (git-ignored).
- The APK is signed with the Android **debug** key: fine for sideloading on your own devices, **not** for Play Store. See `docs/release.md` for a release keystore.
- Bump `expo.version` and `expo.android.versionCode` in `app.json` before each distributed release (currently `1.0.0` / `1`).
- Cloud alternative (no local toolchain): `npx eas-cli@latest build -p android --profile preview` (profiles in `eas.json`: `development`, `preview`, `production`).

## First run on a phone

1. Onboarding → allow microphone (and notifications on Android 13+).
2. Model setup: download the speech model (57 MB) and the Hindi model (ML Kit). Wi-Fi only by default.
3. Start meeting → In-person → Audio test (say "Please share the latest build") → Start listening.
4. Turn on airplane mode — captions continue.
5. Tune noise handling in **Settings → Captions → Audio processing**; the live screen's **Controls** shows which processing is actually active.

**Best accuracy:** phone 30–50 cm from the speaker or laptop, laptop on speakers (not headphones) at 60–80 % volume, or a USB-C/lapel microphone.

## Before a public release

- Create a release keystore and bump the version (`docs/release.md`).
- Decide on the speech-model licence: the default Kroko model is **CC-BY-SA**; the NeMo alternative is CC-BY-4.0 (`docs/model-licenses.md`).
- Run the real-device checklist in `docs/release.md` (30/60-minute sessions, airplane mode, laptop-speaker mode, noisy room, same-phone test).

## Honest limitations

- Hinglish is **on-device translation + rules**, not a conversational model. Names are transliterated by ML Kit (add them to the glossary as "Keep in English"). Review important captions; corrections are saved.
- Latency targets (<1 s interim, 1–3 s final) depend on the phone. Measure in Diagnostics (real-time factor, queue depth, dropped frames).
- The voice filter removes non-speech noise, but **cannot separate the meeting speaker from another person talking nearby**.
- Same-phone Meet/Zoom/Teams call audio is generally **not capturable** on Android. Use laptop speakers + phone microphone.
- No speaker labels: the engine does not identify speakers.
- In development builds, editing code during a meeting (Fast Refresh) resets in-memory state; release builds are unaffected.

See `docs/` for details.
